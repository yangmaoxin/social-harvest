# 用户通过 AI 操作 Social Harvest 速查卡

这页给普通用户和本地 AI agent 一起看。用户只需要说业务目标；AI 负责读文档、检查环境、选择命令、执行任务并读取报告。

## 用户怎么说

| 你想做什么 | 可以直接对 AI 说 | AI 应该做什么 |
| --- | --- | --- |
| 检查能不能跑 | “帮我检查 Social Harvest 今天能不能正常跑，不要写入业务系统。” | 运行 `npm run check`，只检查环境、配置、Chrome/OpenCLI 和登录态 |
| 跑抖音日常 | “跑一下今天的抖音数据，完成后告诉我写入了多少。” | 运行 `npm run daily:douyin`，默认是增量日常全流程 |
| 跑视频号日常 | “跑一下今天的视频号数据。” | 运行 `npm run daily:weixin-channels`，默认是增量日常全流程 |
| 跑全部平台日常 | “今天所有平台都跑一下。” | 运行 `npm run daily:all` |
| 只跑某一块 | “只跑视频号私信。” / “只跑抖音指标。” | 用户层不再拆分；运行对应 `daily:*` 全流程，必要时说明会顺带刷新相关链路 |
| 补跑失败 | “刚才失败了，按报告补跑一下。” | 找到最近 `daily-report.json` 或 `task-report.json`，运行 `npm run daily:failed -- <报告文件>` |
| 历史补齐 | “把抖音历史全量补齐。” | 运行对应 `history:*`，这是显式历史全量 |
| 先试一下 | “先试跑，不要写入业务系统。” | 只跑 smoke / dry-run，不写 SCRM |
| 写飞书 | “把这次结果发到飞书多维表格。” | 已有产物用 `npm run publish:feishu -- ...`，本次同步只写飞书则给日常命令声明 `--sink feishu` |
| 远端看进度 | “远端页面也要看到进度。” | 只有此时才用 `npm run share:run -- ... -- <采集命令>` |

## 默认规则

- 用户说“同步”“跑今天数据”“更新业务系统”，默认是正式同步，会按默认 sink 写入，当前默认是 SCRM / 业务系统。
- 用户说“试跑”“先看看”“不要写入”，才使用不写库的试运行。
- 用户没说平台时，单平台配置可直接跑；多平台配置只追问“抖音、视频号，还是全部平台？”。
- 用户没说飞书时，不写飞书；用户说“只写飞书”时，声明 `--sink feishu`，不要同时写 SCRM。
- 用户没说历史、全量、从头抓完时，不用 `history:*`。
- 用户说“只跑内容/私信/指标”时，也不要让用户选单模块命令；优先跑日常全流程，失败恢复用 `daily:failed`。
- AI 不要让用户选择 `--apply`、`dry-run`、`task:plan`、`task:run` 或多个 `--`。
- 终端里不要向用户展示原始 JSON；采集产物和排障细节留在报告文件里，汇报时转成用户能看懂的业务摘要。

## 抖音 / 视频号日常口径

`npm run daily:douyin` 和 `npm run daily:weixin-channels` 是默认日常，不是历史全量。它们会跑诊断、作品元信息、账号、评论、弹幕、私信、指标快照和 +1/+N 事件。

评论按下面条件定向抓：

- 新作品且有评论
- 平台评论数比上次作品元信息增长
- 近期作品复查窗口内

平台统计评论数可能包含自己回复、隐藏评论或不可见评论；SCRM 评论明细只保留实际可见且非自己的评论/回复。因此平台统计数和数据库明细数不一致时，不作为日常反复补抓条件。

## AI 汇报结果时要说清楚

任务结束后，AI 必须读取输出目录里的 `task-report.json` 或 `daily-report.json`，不要只看终端最后几行。

汇报优先包含：

- 任务是否成功
- 作品、评论、弹幕、私信、账号、指标分别处理了多少
- 写入业务系统的数量或本轮实际新增数量
- 失败或跳过步骤
- 报告文件路径

## 命令模式取舍

当前推荐保持一线命令少而稳定：

- `check`
- `daily:*`
- `history:*`
- `daily:failed`
- `publish:feishu`
- `sink:run`
- `share:run`

不要再为“fast”“quick”“normal”这类实现细节新增用户入口。速度差异应由 AI 根据日常、校准、历史、补跑这些业务词自动选择。
