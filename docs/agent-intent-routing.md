# Social Harvest Agent Intent Routing

更新日期：2026-05-25

这份文档说明：当用户没有把平台、日期、任务范围或是否写库说得很具体时，agent 应该怎么理解、什么时候直接执行、什么时候追问。

核心原则：

```text
能安全默认的，不打断用户。
有业务风险的，先问清楚。
用户说“同步”，默认按平台 sink 配置正式写入，当前默认是 SCRM / 业务系统。
用户说“试跑 / 不要写入”，才不写库。
用户没说“飞书 / 多维表格 / 展示表”，不要写飞书。
追问只问业务选项，不问内部命令参数。
```

## 默认值

| 缺失信息 | 默认处理 |
| --- | --- |
| 没说日期 | 默认今天 |
| 没说平台，但配置只有一个启用平台 | 使用该平台 |
| 没说平台，且配置有多个启用平台 | 追问平台，或在用户说“全部/都跑”时使用全平台计划 |
| 没说任务范围，只说“数据/今天数据/同步一下” | 使用日常同步计划 |
| 没说是否写入 | 如果用户说“同步/跑今天数据/更新”，默认按平台 sink 配置正式写入，当前默认是 SCRM / 业务系统 |
| 没说是否写飞书 | 不写飞书；只有明确提到“飞书 / 多维表格 / 展示表 / 发到飞书”才执行飞书 sink 或飞书发布 |
| 没说输出格式 | 用业务语言汇报，不直接贴 JSON |
| 没说展示方式 | 使用命令默认的人类可读进度展示 |

抖音平台的默认含义：

- 用户只说“抖音”时，默认走 **抖音创作者中心正式主线**。
- 只有用户明确说“抖音前台”“公开主页”“前台公开页”时，才走抖音前台公开页链路。

## 直接执行

这些话术可以直接映射为正式同步：

| 用户说 | Agent 理解 |
| --- | --- |
| “跑一下今天的数据” | 今天，日常同步，正式写库 |
| “同步一下抖音” | 今天，抖音创作者中心正式同步 |
| “把视频号更新一下” | 今天，视频号正式同步 |
| “处理一下今天的评论” | 今天，评论相关同步；如果平台唯一则直接跑，否则追问平台 |
| “更新业务系统” | 正式同步并写入 SCRM / 业务系统 |
| “今天数据都跑一下” | 全平台日常同步；如果没有全平台计划或配置不完整，先说明缺口 |
| “弄一下数据” | 如果只有一个启用平台，按今天日常同步；多个平台则追问平台 |
| “把今天的东西更新一下” | 今天，日常同步，正式写库 |
| “看看今天有没有新数据” | 先检查/读取最近报告；如果用户要同步，再正式写库 |

执行前可以简短提示：

```text
我会按今天的数据做正式同步，并按默认 sink 写入 SCRM / 业务系统。先检查环境，然后执行。
```

不要要求用户补充 `--apply`、`task:plan`、`task:run`、`dry-run` 这类内部参数。

不要把普通同步扩展成“同时写飞书”。飞书是显式外部发布目标，不是 SCRM 入库的默认副作用。用户明确说“只写飞书”时，应把目的地声明成 `--sink feishu`，而不是再同时写 `scrm`。

## 展示意图

展示方式只影响终端和远端页面怎么显示进度，不改变是否写库。

不要为了隐藏原始 JSON 把已有 `--display detailed` 入口改成 `compact`。如果输出看不懂，应该过滤/转换 JSON，并在任务结束后读取 `daily-report.json` 或 `task-report.json` 汇报。

| 用户说 | Agent 理解 |
| --- | --- |
| “正常跑”“同步一下”“跑今天数据” | 使用命令默认的人类可读进度展示 |
| “详细看看过程” | 本机详细展示；优先使用 `daily:*` / `history:*` 的默认详细展示 |
| “显示抓取进度”“让我看到每一步” | 本机详细展示；排障时由 agent 直接调用内部 runner |
| “远端页面也要看到” | 远端详细展示，使用 `share:run` 包裹任务 |
| “同步到服务器展示” | 远端详细展示，使用 `share:run` 包裹任务 |
| “另一台电脑也要看进度” | 远端详细展示，使用 `share:run` 包裹任务 |
| “看原始事件”“调试 TASK_EVENT” | 调试展示，使用 `--display jsonl` |
| “不要输出日志”“静默跑” | 静默展示，使用 `--display silent` |

远端详细展示不是主流程。只有用户明确提到远端页面、服务器同步或另一台电脑观看进度时，才使用 `share:run`。

如果需要远端详细展示但缺少服务器地址，先追问：

```text
远端展示需要服务器地址。请提供类似 http://127.0.0.1:8001 的地址。
```

不要问用户多个 `--` 怎么写；那是 agent 的命令拼接责任。

## 试运行和检查

这些话术不要写库：

| 用户说 | Agent 理解 |
| --- | --- |
| “看看今天能不能跑” | 环境检查 / diagnostic |
| “检查一下 Social Harvest” | preflight + 必要 diagnostic |
| “先试一下” | 试运行，不写库 |
| “先预览一下” | dry-run / preview，不写库 |
| “不要写入业务系统” | 不写库 |
| “别入库，先看看结果” | 不写库，跑 smoke / preview |
| “验证一下链路” | 不写库，跑 smoke / preview |
| “安装完先测一下” | preflight + 不写库 smoke |

如果用户说“试一下同步”，按试运行处理，因为“试一下”比“同步”更明确地表达了安全预演意图。

## 必须追问

下面情况不要猜：

| 情况 | 追问方式 |
| --- | --- |
| 多个平台启用，但用户只说“处理一下数据” | “你想跑抖音、视频号，还是全部平台？” |
| 用户说“处理评论”，但平台不明确且没有默认平台 | “要处理哪个平台的评论？” |
| 用户说“最近数据”，但没有业务默认窗口 | “你想看今天、近 7 天，还是指定日期？” |
| 用户要求“导出/发给谁/发送报告” | 先确认目标和格式 |
| 用户要求“清理/删除/重置/覆盖数据” | 必须确认对象、范围和风险，不直接执行 |
| 用户要求修改配置、数据库结构或凭据 | 必须说明影响并确认 |
| 需要直接执行 SQL 写库、删库、改库 | 不要直接执行；优先走项目 CLI / runner，必要时先确认表名、范围和影响行数 |

追问要短，不要把内部命令暴露给用户。

## 失败和复盘

这些话术都应该读取任务报告：

| 用户说 | Agent 动作 |
| --- | --- |
| “刚才怎么失败了” | 找最近输出目录，读取 `task-report.json` |
| “看看哪里有问题” | 读取 report，再按 `failure_category` 和 `next_actions` 汇报 |
| “重新跑一下刚才那个” | 先读取上一轮 report，确认是否可重试，再按 `repro_command` 或计划重跑 |
| “把结果总结一下” | 读取最近 `task-report.json`，输出业务摘要 |

不要只看终端最后几行日志。

## 高风险词

用户出现这些词时，agent 应该暂停并确认：

- 删除
- 清空
- 重置
- 覆盖
- 批量修改
- 改数据库
- 改配置
- 迁移数据
- 发给别人
- 上传
- 公开

确认时说清楚影响范围，例如：

```text
这会修改业务系统里的历史数据。请确认要处理的平台、日期范围和数据类型。
```

即使是在失败恢复里，agent 也不能自行删除 `scrm_*` 表里的历史数据。配置里的账号 `id`，例如 `main`，只是本地别名；写库前必须确认使用的是真实平台 `account_id`。

## 示例

### 模糊但可默认

用户：

```text
今天抖音跑一下。
```

Agent：

```text
我会按今天的抖音数据做正式同步，并写入 SCRM / 业务系统。先检查环境，然后执行。
```

动作：

```bash
npm run check
npm run daily:douyin
```

### 模糊且需要追问

用户：

```text
处理一下评论。
```

如果多个平台启用，Agent 应该问：

```text
你想处理抖音评论、视频号评论，还是全部平台的评论？
```

### 明确试运行

用户：

```text
先看看链路通不通，别写进去。
```

Agent：

```text
我会跑不写库的试运行，只检查链路和少量样本。
```

动作：

```bash
node scripts/task-runner.js plan --config tasks/smoke-douyin-public.json --output-dir samples/tasks/smoke-douyin-public-demo
```

## 维护规则

- 新增计划任务时，补充它对应的自然语言入口。
- 新增平台时，补充平台别名和追问规则。
- 如果真实用户连续两次用同一种模糊说法让 agent 判断错，就把该说法加入本文件。
- 本文件只做路由规则；具体命令和失败恢复仍以 [Social Harvest Agent Runbook](agent-runbook.md) 为准。
