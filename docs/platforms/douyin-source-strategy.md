# 抖音数据源双方案策略

这份文档定义抖音当前正式方向：不再把“抓自己”和“抓别人”混成一条主线，而是按权限边界拆成两套方案。

## 1. 总体原则

### 抓自己

- 主来源：创作者中心
- 辅来源：前台公开页
- 适用范围：创作者中心作品、创作者中心评论管理、创作者中心弹幕管理、创作者中心私信、后台指标和管理字段

### 抓别人

- 主来源：前台公开页
- 不使用：创作者中心
- 适用范围：公开主页作品、公开视频评论、公开回复、公开资料

一句话规则：

- **自己账号 = 创作者中心主线，前台辅助校验**
- **别人账号 = 前台唯一主线，不碰创作者中心**

## 2. 为什么这样拆

这两类任务本质上不是同一种抓取：

- 创作者中心依赖本人登录态，适合后台管理数据。
- 前台只依赖公开可见内容，适合外部账号研究。
- 弹幕、私信、后台状态和运营指标天然偏向创作者中心。
- 公开主页作品、公开评论和公开回复天然偏向前台。

如果把两类任务继续揉成一个“抖音默认抓取”，会持续出现：

- 默认入口含糊
- 是否需要登录态不清楚
- 前后台字段语义打架
- 桌面端任务名称和计划难以解释

## 3. 数据域归属

| 数据域 | 抓自己 | 抓别人 | 备注 |
| --- | --- | --- | --- |
| 公开作品主档 | 前台辅助 / 可校验 | 前台主线 | 公开字段最适合前台 |
| 后台作品状态/指标 | 创作者中心主线 | 不适用 | 例如状态、可见性、管理指标 |
| 公开评论/回复 | 前台辅助 / 继续观察 | 前台主线 | 当前仍保留前台覆盖能力 |
| 后台评论管理字段 | 创作者中心主线 | 不适用 | UID、IP、管理侧关系字段 |
| 弹幕 | 创作者中心主线 | 前台仅探针 | 目前正式可用链路是后台 |
| 私信 | 创作者中心主线 | 不适用 | 当前正式链路已是后台 |

## 4. 当前落地策略

### 自己账号任务

推荐任务：

- `douyin / creator-content`
- `douyin / creator-account`
- `douyin / creator-danmaku`
- `douyin / creator-messages`
- `sink-runner / scrm`
- `sink-runner / feishu`

推荐计划：

- `npm run daily:douyin`：创作者中心增量日常计划
- `npm run daily:douyin:full`：创作者中心完整慢速校准计划

当前 `npm run daily:douyin` 已经不只是“抓样本”，而是一条默认的自己账号增量正式流程：先抓作品元信息对比数据库基线，再按新增/评论数增长/弹幕数增长/近期复查定向抓评论和弹幕。

1. `creator-center`
2. `sink-runner --sink-apply`

`creator-center` 只产出平台采集文件；`sink-runner` 再把内容、账号、弹幕、私信、metric snapshot 和 metric delta 写入声明的 sink。数据库是 `sink: scrm`，飞书是 `sink: feishu`。

其中评论主表默认按 creator-only 写入；只有显式提供前台样本并开启 `--supplement-public-ip` 时，才额外补 `ip_location`。

具体怎么跑、什么时候用 `--account-bound`、什么时候补评论 IP、验收看哪些表，统一看：

- [抖音自己账号正式运行手册](./douyin-self-runbook.md)

前台在这个模式下只作为：

- `account_guard`
- 公开字段补充
- 异常校验

### 别人账号任务

推荐任务：

- `douyin / harvest`

推荐计划：

- `npm run history:douyin-public`：公开主页历史补抓
- `node scripts/task-runner.js plan --config tasks/daily-douyin-public.json`：公开主页日常排障计划

这个模式下不读取创作者中心，不依赖创作者中心登录态。

## 5. 主表写入规则

这份文档只定义“抓自己 / 抓别人”的来源分流；主表如何写入，按下列更严格规则执行：

- 抓取层允许双线
- 主表写入层只允许单口
- 自己账号场景下，创作者中心是主来源，前台只做补充和校验
- 别人账号场景下，前台是唯一主来源

详细规则见：

- [抖音主表写入策略](douyin-main-table-write-strategy.md)

## 6. 桌面端要求

桌面端必须把两种任务明确分开，不再只写“抖音抓取”：

- `公开主页抓取`
- `创作者中心抓取`
- `创作者中心私信导出`

计划层至少区分：

- `每日抖音（创作者中心）`
- `抖音公开主页每日任务`

## 7. 本阶段不做的事

本阶段先不做下面这些大动作：

- 不把创作者中心作品/评论直接改写成主表唯一来源
- 不把前台弹幕正式接入主流程
- 不把“抓自己”和“抓别人”强行写成同一套入库逻辑
- 不把前台评论继续当成自己账号评论主线的硬依赖

## 8. 当前执行顺序

1. 先把命名、文档、计划样本、桌面端任务标签拆开
2. 再把默认日计划拆成“创作者中心”和“公开主页”两种
3. 自己账号评论主线切到 creator-only 默认，前台只保留可选 `ip_location` 补充
4. 按真实样本继续评估作品和评论是否进一步后台化
